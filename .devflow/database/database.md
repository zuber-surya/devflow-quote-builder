# Database

**Source of truth:** `prisma/schema.prisma` (already implemented, Phase 0). This file is a navigable summary — check the schema directly for exact types/constraints.

## Entities
- `User` — email/password (hashed), 1:1 `BusinessProfile`, owns Customers/Products/Quotes/Invoices/RefreshTokens.
- `RefreshToken` — JWT refresh tokens for Flutter mobile auth.
- `BusinessProfile` — name, contact, address, tax number (GSTIN), logo, currency (default `INR`), branding fields.
- `Customer` — contact/address/tax fields, notes. Unique per `(userId, customerName)`.
- `Product` — name, description, `sku` (optional), price, taxRate, unit. Unique per `(userId, sku)`.
- `Quote` / `QuoteItem` — `quoteNumber` (`Q-{year}-{00001}`), status enum (`DRAFT/SENT/ACCEPTED/REJECTED/EXPIRED/CONVERTED`), server-calculated subtotal/tax/total, discount. Conversion link lives on `Invoice.quoteId` (unique FK back to the source quote) — a converted quote is found via `quote.invoice`, not a duplicate FK on Quote itself (see decisions.md, fixed a Prisma relation bug 2026-08-15).
- `PasswordResetToken` — `token` (sha256 hash, never raw), `expiresAt`, `usedAt` (single-use), FK to `User`.
- `Invoice` / `InvoiceItem` — `invoiceNumber` (`INV-{year}-{00001}`), `quoteId` back-reference, `paidAmount`/`paymentStatus` enum (`UNPAID/PARTIALLY_PAID/PAID/OVERDUE`), `dueAt`.

## Conventions
- All money fields `NUMERIC` (Decimal in Prisma) — never float. Quantities `NUMERIC(10,4)`, unit prices `NUMERIC(12,2)`, totals `NUMERIC(14,2)`.
- Every business entity has a direct `userId` FK — data isolation enforced at the schema level, not just query-level.
- Quote/Invoice numbers are unique per `(userId, number)`, not globally unique — each user's sequence is independent.
- Line item totals (`lineTotal`) and document totals (`subtotal`/`taxAmount`/`total`) are always server-recalculated, never trusted from client input.

## Note on scope
`Product.sku` exists in the schema as optional, though the client-requirements PRD doesn't list SKU as a required field. Low-risk addition (nullable, doesn't block anything) — flagged in `questions/open-questions.md` rather than reverted, since it's already implemented and harmless.

## Numbering implementation
No dedicated `number_sequences` table currently — numbers generated by querying `MAX` per `(userId, year)` prefix at creation time (see `CRITICAL_BLOCKERS.md` Blocker #6 for the algorithm). Acceptable for MVP concurrency levels (single user writing at a time); revisit if concurrent-write races become an issue.
